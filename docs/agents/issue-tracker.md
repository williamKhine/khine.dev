# GitHub Issues

Use `gh` to create, read, list, label, comment on, and close issues in `williamKhine/khine.dev`.
Pin the repo with `--repo williamKhine/khine.dev` when the target could be ambiguous.

Use native GitHub sub-issues for parent-child relationships and native issue dependencies for blockers.
If unavailable, record `Part of #<parent>` or `Blocked by: #<issue>` in the issue body.
An issue is unblocked when all of its blockers are closed.

Publishing a ticket means creating a GitHub issue. Fetching a ticket means reading its body, labels, and comments.

**PRs as a request surface: no.**
